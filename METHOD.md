# Методика проверки функций анализа последовательностей

## 0. Паспорт

| Поле | Значение |
|---|---|
| Задача | проверить корректность функций `src/seqstats.py`, которые считают состав, GC и ORF для белков и генов SNCA, APP, MAPT, HTT |
| Дисциплина | биология |
| Вариант верификатора | тесты на свойствах (Hypothesis), сверка с Biopython, мутационная проверка, договор о данных |
| Методика приведена к шаблону | 2026-11-09 |
| Метки git | `exp-verifier` (неделя 6), `hw2` (сдача) |

## 1. Замысел

Цель — проверить корректность функций модуля `src/seqstats.py`, используемых для анализа белковых и нуклеотидных последовательностей генов SNCA, APP, MAPT и HTT. Проверяются нормализация, аминокислотный состав, GC-содержание, обратный комплемент и поиск ORF.

- **Вопрос:** совпадают ли расчёты с определениями и с независимой реализацией (Biopython) на любых допустимых входах и на реальных записях UniProt?
- **Гипотеза:** да; любая внесённая ошибка в этих функциях будет поймана тестами.
- **Зачем:** результаты расчётов войдут в итоговую работу, и тихая ошибка в одной функции исказила бы все числа сразу. Поэтому проверка должна не только проходить на правильном коде, но и падать на неправильном.

## 2. Постановка

Используются три подхода:

1. Property-based тестирование с библиотекой Hypothesis: проверяются свойства функций на автоматически генерируемых последовательностях.
2. Сравнение с независимой реализацией Biopython: аминокислотный состав и GC-содержание должны совпадать с результатами библиотеки.
3. Мутационное тестирование: семь искусственно изменённых реализаций (мутантов) используются для проверки того, что тесты способны обнаруживать ошибки.

Дополнительно проверяются формат, непустота и допустимый алфавит реальных FASTA-файлов из `data/`.

| Что | Значение |
|---|---|
| Что меняется | входные последовательности: порождённые Hypothesis и четыре реальных белка |
| Что фиксируется | код `src/seqstats.py`, версии пакетов (`requirements.txt`), профили Hypothesis |
| Что измеряется | прошла проверка или нет; расхождение с Biopython |
| Базовая линия | Biopython (`ProteinAnalysis`, `gc_fraction`) |

**Договор о схеме данных (реальные FASTA):**

- последовательность непустая;
- алфавит — только 20 стандартных аминокислот;
- длина равна значению в `checks/expected_lengths.csv` (эталон должен быть сверен автором со страницами UniProt; результат сверки записан в `REPORT.md`);
- (правило «последовательности разных белков различны» тестом не реализовано)

## 4. Код и окружение

- Код проверяемых функций: `src/seqstats.py`.
- Команда запуска: `python -m pytest checks -q`
- Окружение: Python 3.12; пакеты — `requirements.txt` (biopython, hypothesis, pytest).
- В Hypothesis заданы два профиля: `default` — 200 примеров с детерминированной генерацией; `explore` — 300 примеров, seed задаётся параметром `--hypothesis-seed` (используются 0, 1 и 2).

## 5. Верификатор

**Что проверяет** (свойства):

| № | Свойство | Тест |
|---|---|---|
| P1 | сумма аминокислотного состава равна длине последовательности | `test_p1_composition_sum` |
| P2 | состав не зависит от порядка остатков | `test_p2_composition_order_invariant` |
| P3 | GC-содержание в диапазоне [0, 1]; для последовательностей только из G/C оно равно 1, только из A/T — 0 | `test_p3_gc_bounds` |
| P4 | GC-содержание не меняется при переходе к обратному комплементу | `test_p3b_gc_strand_invariant` |
| P5 | двойное обратное комплементирование возвращает исходную ДНК | `test_p4_revcomp_involution` |
| P6 | нормализация идемпотентна: повторная нормализация не меняет результат | `test_p5_normalize_idempotent` |
| P7 | каждый найденный ORF начинается с ATG, заканчивается стоп-кодоном, имеет длину, кратную трём, и не содержит внутренних стоп-кодонов | `test_p6_orfs_wellformed` |
| P8 | заранее встроенный ORF обнаруживается при разных смещениях | `test_p7_planted_orf_found` |

Дополнительно: совпадение состава и GC с Biopython (`test_oracle_biopython`); для состава требуется точное равенство, для GC абсолютная разность меньше 1e-12. Каждое свойство проверено на своём мутанте (`test_mutant_p1_caught` … `test_mutant_p7_caught`).

На реальных данных (`checks/test_real_data.py`): длины четырёх белков, заголовок и алфавит, состав против Biopython, состав SNCA против таблицы из `diary.md`, согласие скрипта `src/analyze_snca.py` с `seqstats`.

**Команда:** `python -m pytest checks -q`

**Чего не проверяет:** см. раздел 9.

## 6. Шаги проверки

| Шаг | Команда | Условие перехода к следующему шагу |
|---|---|---|
| 1. Договор о данных | `python -m pytest checks/test_contract.py checks/test_real_data.py -q` | все четыре FASTA прошли; иначе дальше не идём |
| 2. Свойства и Biopython | `python -m pytest checks -q` | все тесты зелёные на профиле `default` |
| 3. Мутанты | `python -m pytest checks -q -k mutant` | все семь исходных мутантов пойманы |
| 4. Повторы | `HYPOTHESIS_PROFILE=explore python -m pytest checks -q --hypothesis-seed=N`, N = 0, 1, 2 | все три запуска зеленые |
| 5. Повторная проверка мутантов | семь исходных мутантов проверены на seed 0–9 профиля explore | все мутанты пойманы на каждом seed (`results/mutants_explore_seeds.txt`) |
| 6. Внесенная ошибка | ветка с ошибкой в `gc_content`, `python -m pytest checks -q` | до исправления: 3 failed, 42 passed; после исправления: 45 passed |
| 7. Дополнительные мутации | `scripts/mutate.py` | все семь дополнительных ошибок обнаружены (`results/mutation_extra.txt`) |

## 7. Правило принятия

Реализация считается прошедшей проверку, если все тесты завершаются успешно, результаты сравнения с Biopython укладываются в заданные допуски, реальные FASTA-файлы соответствуют договору о данных, а все семь искусственных мутантов обнаруживаются тестами.

1. **Метрика:** число упавших проверок; принимается значение 0.
2. **Повторы:** один детерминированный прогон (профиль `default`, 200 примеров на свойство) и 3 запуска профиля `explore` с seed 0, 1, 2 (по 300 примеров).
3. **Сравнение:** состав совпадает с Biopython точно; GC — с допуском 1e-12.
4. **Порог:** допуск 1e-12 — точность числа с плавающей точкой; других порогов нет.
5. **Если проверка упала:** проверяется сама реализация и корректность свойства. Допуски и условия не ослабляются только ради успешного прохождения теста.

## 8. Бюджет

Время счета — меньше минуты (полный набор около двух секунд).

## 9. Ограничения

**Ограничения.** Тестирование охватывает конечное число сгенерированных последовательностей и не доказывает корректность для всех возможных входов. Мутанты представляют только семь выбранных типов ошибок. Реальные CDS четырёх генов не анализируются: в `ids.csv` лежат NCBI Gene ID, а не нуклеотидные записи, поэтому GC и ORF проверяются на синтетической ДНК. Биологическая значимость найденных ORF, вырожденные нуклеотидные коды, интроны и сплайсинг не входят в область проверки. Эталоны длин имеют смысл только после сверки со страницами UniProt.
