## 1. Задача и место верификатора

`[написано автором при помощи модели: структурирование материала, организация разделов и уточнение формулировок]`

Проект характеризует белки и гены, связанные с нейродегенеративными заболеваниями: SNCA (UniProt P37840), APP (P05067), MAPT (P10636) и HTT (P42858). Для каждого считаются длина, аминокислотный состав, GC-содержание нуклеотидной последовательности и открытые рамки считывания (ORF). Все расчеты собраны в модуле `src/seqstats.py` (функции `normalize`, `aa_composition`, `gc_content`, `revcomp`, `find_orfs`, `read_fasta`), а итоги записываются в `diary.md`.

Проверяется именно этот модуль. Он порождает числа для всей остальной работы: тихая ошибка в одной функции (например, GC без учета C) исказила бы все результаты сразу и осталась бы незамеченной, потому что код при этом выполняется без исключений. Поэтому верификатор должен не только проходить на правильном коде, но и падать на неправильном, и это отдельно показано (раздел 6).

## 3. Верификатор

`[написано автором при помощи модели: структурирование материала, организация разделов и уточнение формулировок]`

- **Что проверяет:** функции `normalize`, `aa_composition`, `gc_content`, `revcomp`, `find_orfs` выполняют заявленные свойства; состав и GC совпадают с Biopython; четыре FASTA из `data/` соответствуют договору; каждое свойство способно поймать свою ошибку.
- **Как устроен:** всего 45 тестов.
  - `checks/test_props.py` — 9 тестов свойств и сверки с Biopython и 7 тестов «проверки проверки» (мутантов);
  - `checks/test_known.py` — 6 тестов на известные значения и обе цепи ORF;
  - `checks/test_contract.py` — 9 тестов договора о схеме FASTA;
  - `checks/test_real_data.py` — 14 тестов на четырех реальных белках;
  - `checks/conftest.py` — профили Hypothesis: `default` (200 примеров, `derandomize=True`) и `explore` (300 примеров, seed через `--hypothesis-seed`).
- **Генераторы входов:** белки из 20 аминокислот длиной 1–300; ДНК из ACGT длиной 3–600; ДНК из восьми кодонов (ATG, три стопа, четыре смысловых) для ORF; «грязные» строки с пробелами, переводами строк, цифрами и разным регистром для нормализации.
- **Чего не проверяет:** см. раздел 8.

Нумерация свойств ниже — по `METHOD.md`; в именах тестов она сдвинута (в коде `p3b` — отдельное свойство).

| № | Свойство | Почему должно выполняться | Тест |
|---|---|---|---|
| P1 | сумма состава равна длине | каждый остаток считается ровно один раз | `test_p1_composition_sum` |
| P2 | состав не зависит от порядка | состав — мультимножество | `test_p2_composition_order_invariant` |
| P3 | GC в [0, 1]; `GC`-повтор дает 1, `AT`-повтор дает 0 | физические границы доли | `test_p3_gc_bounds` |
| P4 | GC не меняется при обратном комплементе | пара G–C комплементарна самой себе | `test_p3b_gc_strand_invariant` |
| P5 | обратный комплемент — инволюция | дважды перевернуть и дополнить — исходная цепь | `test_p4_revcomp_involution` |
| P6 | нормализация идемпотентна | повторная очистка ничего не меняет | `test_p5_normalize_idempotent` |
| P7 | каждый ORF: начинается с ATG, длина кратна 3, стоп в конце, внутренних стопов нет | определение ORF | `test_p6_orfs_wellformed` |
| P8 | внедренный ORF находится при любом сдвиге 0–7 | метаморфическая проверка | `test_p7_planted_orf_found` |
| P9 | состав совпадает с Biopython точно, GC — с допуском 1e-12 | независимая реализация | `test_oracle_biopython` |

Дополнительно к свойствам:

- **Известные значения** (`test_known.py`): `revcomp("AAC") == "GTT"`, `revcomp("ATGC") == "GCAT"`; `normalize(" a1c\n gt\t2") == "ACGT"`; нормализация не меняет чистую ДНК; ORF `ATGGCTAAATAA` находится на прямой и на обратной цепи; граница `min_len` (ORF длиной ровно 9 нт находится при `min_len=9` и не находится при 10). Эти тесты добавлены после подцели G8: общие свойства пропускали ошибки, которые простые известные значения ловят сразу.
- **Договор о данных** (`test_contract.py`, `test_real_data.py`): в заголовке есть идентификатор UniProt и `GN=<ген>` из `data/ids.csv` (коды нарушений `no_accession`); последовательность непустая (`empty`); алфавит — 20 стандартных аминокислот (`bad_alphabet`); длина равна значению из `checks/expected_lengths.csv`; состав четырех белков совпадает с Biopython; состав SNCA совпадает с таблицей из `diary.md` (`checks/expected_snca_diary.json`); скрипт `src/analyze_snca.py` согласован с `seqstats`. Для каждого кода нарушения есть тест на синтетическом плохом файле, так что договор способен падать.
- **Проверка проверки** (`test_mutant_p1_caught` … `test_mutant_p7_caught`): семь заранее написанных неправильных реализаций (состав без последнего остатка; состав первой половины; GC только по G; C комплементарен самому себе; нормализация со сменой регистра вместо приведения; ORF без стопа TGA; ORF только в нулевой рамке). Тест проходит, только если соответствующее свойство **падает** на мутанте.

**Сравнение с базовой линией и правило значимости.** Базовая линия — Biopython: состав совпадает точно, GC — с допуском 1e-12; расхождений нет ни на сгенерированных входах, ни на четырех реальных белках (результат сравнения — все или ничего, на каждом входе один и тот же ответ). Значимостные процедуры из шаблона здесь не применяются по существу, а не по умолчанию: сравниваются не два варианта метода по метрике со случайной оценкой, а реализация с эталоном на идентичных входах. Поэтому парное сравнение по общим seed не требуется (входы для проверяемого кода и для Biopython одни и те же), поправка Холма не нужна (нет семейства из нескольких сравнений вариантов), а роль практического порога играет допуск 1e-12 — точность числа с плавающей точкой, записанный в `METHOD.md` до первого прогона, пункт 4 правила принятия. Выбор лучшего повтора не производится: принимается только вариант, при котором падений 0 во всех прогонах.

Проверка сравнивается с независимой базовой линией (Biopython) для состава и GC. Для `revcomp`, `normalize` и `find_orfs` независимой реализации нет; они проверены свойствами и известными значениями (раздел 8).

Итог по правилу принятия: число упавших проверок 0 во всех прогонах; допуск 1e-12 не потребовался (расхождений нет); семь мутантов пойманы; договор о данных выполнен. Реализация принята.

## 8. Ограничения

`[написано автором при помощи модели: структурирование материала, организация разделов и уточнение формулировок]`

- Тесты на свойствах проверяют конечное число входов и не доказывают корректность для всех входов.
- Семь мутантов и семь мутаций реального кода — выбранные типы ошибок; это не полный перечень возможных ошибок.
- **Нуклеотиды не реальные.** В `data/ids.csv` лежат NCBI Gene ID, а не нуклеотидные записи, поэтому GC, обратный комплемент и ORF проверены только на синтетической ДНК (алфавит ACGT). Реальные CDS четырех генов не анализируются; вырожденные коды (N, R, Y и др.), интроны и сплайсинг не входят в область проверки; биологическая значимость найденных ORF не оценивается.
- **Независимая сверка есть не для всех функций.** Biopython служит эталоном только для состава и GC. `revcomp`, `normalize` и `find_orfs` проверены свойствами и известными значениями; независимой реализации для них нет.
- **Полнота поиска ORF не проверяется.** Свойства P7 и P8 показывают, что найденные ORF корректны, а внедренный ORF находится; но нет проверки, что функция находит все ORF в произвольной последовательности. Поведение для вложенных ORF и для нескольких ATG в одной рамке тестами не специфицировано.
- **Эталон длины не вполне независим.** `checks/expected_lengths.csv` защищает от порчи или подмены файлов, но для APP, MAPT и HTT значения взяты из тех же загруженных записей. Независимая ручная сверка (страница UniProt плюс пересчет командами оболочки) задокументирована только для SNCA (`diary.md`, запись от 2026-11-04). Совпадение с Biopython не доказывает, что скачана именно нужная запись.
- **Договор о данных неполный.** Правило «последовательности разных белков различны» тестом не реализовано. Регулярное выражение для идентификатора допускает любую запись вида `sp|…|` или `tr|…|`. Поведение `gc_content` на пустой строке не проверено.
- Результаты получены в одном окружении (Python 3.12.8, пакеты из `requirements.txt`); на других версиях Hypothesis набор генерируемых примеров может отличаться.
- Верификатор проверяет только `src/seqstats.py` и согласованность `src/analyze_snca.py` с ним; остальной код проекта и биологические выводы не проверяются.
